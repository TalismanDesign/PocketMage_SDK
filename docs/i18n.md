# Internationalization (i18n)

The SDK contains the translation engine, the generator tooling, and the base
catalog of strings used by SDK modules. Each app owns a catalog with its own
strings. At build time the catalogs are merged into a single enum and set of
string tables per firmware image.

## Layout

```text
PocketMage_SDK/
  pocketmage_i18n/
    pocketmage_i18n.h / .cpp          # runtime engine (I18n class)
    languages/                        # base catalog (SDK-owned strings)
      en/pocketmage_i18n.po
      fr/pocketmage_i18n.po
      fr/pocketmage_i18n.aliases
      es/...  de/...
    tools/
      gen_i18n.py                     # merger, generator, and build hook
    tests/
      test_gen_i18n.py
```

An app adds one catalog directory of its own:

```text
<app>/src/i18n/
  en/pocketmage_i18n.po
  fr/pocketmage_i18n.po
  fr/pocketmage_i18n.aliases
  ...
```

A catalog directory contains one subdirectory per language, named by the
language code. `en` is required and is authoritative for that catalog's
string order.

## Catalog format

Standard gettext `.po`. `msgctxt` is the `StringID` enum name; `msgid` is the
English text; `msgstr` is the translation. The `en` file carries a
`# Languages:` directive in its leading comment block:

```po
# PocketMage OS English Translations
# Languages: en fr es de

msgctxt "STR_SYS_HELLO"
msgid "Hello"
msgstr "Hello"
```

That directive, in the **base** catalog, is the single source of truth for
the language list and order. Every catalog's `en` file defines the order of
the strings that catalog contributes; that catalog's other languages must
list the same `msgctxt`s, with the same `msgid`s, in the same order.

A language missing from a catalog falls back to that catalog's English text,
so an app can ship an English-only catalog without translating anything else.

### Aliases

`pocketmage_i18n.aliases` maps folded, lowercase user input to a `StringID`.
It is optional and only defined for non-English languages:

```text
annuler -> STR_KB_APP_CANCEL
```

Folding strips diacritics (`Paramètres -> parametres`). Aliases from all
catalogs are concatenated per language; a key that folds to the same value
twice is a build error.

## Ownership

| Owner            | Namespaces                                                                                                                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SDK base catalog | `STR_KB_*`, `STR_SD_*`, `STR_WIFI_*`, `STR_SYS_*`, `STR_TOUCHPAD_*`, `STR_OLED_*`, `STR_FRAME_*`, `STR_INFO/GOOD/SAVED_*`, `STR_DAY_*`, `STR_MONTH_*`                                                                            |
| App catalog      | `STR_TERM_*`, `STR_ONBOARD_*`, `STR_SSH_*`, `STR_SETTINGS_*`, `STR_CAL_*`, `STR_UTILS_*`, `STR_LOCK_*`, `STR_HOME_*`, `STR_TASKS_*`, `STR_FILEWIZ_*`, `STR_APPLOADER_*`, `STR_COMM_*`, `STR_USB_*`, `STR_LEX_*`, `STR_JOURNAL_*` |

`msgctxt`s must be globally unique across the merged catalogs; reusing a name
in an app catalog that the SDK already defines is a build error. SDK modules
only ever reference SDK namespaces, so SDK code is unaffected by which app
catalog is merged in.

## Generator

`tools/gen_i18n.py` merges the catalogs in command-line order and writes
`pocketmage_i18n_gen.h` and `pocketmage_i18n_gen.cpp`:

```sh
python3 pocketmage_i18n/tools/gen_i18n.py \
    --catalog pocketmage_i18n/languages \
    --catalog ../app/src/i18n \
    --out-dir <build-dir>
```

`--catalog` is repeatable; the first catalog is the base. With no arguments
the tool generates the SDK's own base catalog into `pocketmage_i18n/`, so a
bare SDK checkout builds standalone.

The merge keeps the base strings first, appending each later catalog in turn.
Since every enum value equals its index in the merged order, this is stable:
adding an app catalog never changes SDK string values.

### Validation

The generator exits non-zero, aborting the build, on any of:

- a missing `# Languages:` directive in the base `en` file, or `en` not first;
- a `msgctxt` that is not `[A-Z][A-Z0-9_]*`;
- a duplicate `msgctxt` within a catalog or across catalogs;
- a non-`en` file whose `msgctxt` set, order, or `msgid`s differ from that
  catalog's `en`;
- a duplicated folded alias;
- the indexed helper ranges missing, inverted, overlapping, or out of order.

### Indexed helper ranges

Four ranges are indexed by the runtime helpers (`appName()`, `dayName()`,
`monthName()`, `kbAppName()`). They must remain contiguous blocks, in this
order:

| Range                                      | Members                               |
| ------------------------------------------ | ------------------------------------- |
| `STR_KB_APP_CANCEL` .. `STR_KB_APP_LOADER` | app list in the keyboard app switcher |
| `STR_GRID_TXT` .. `STR_GRID_LOADER`        | app list in the launcher grid         |
| `STR_DAY_SUNDAY` .. `STR_DAY_SATURDAY`     | weekdays                              |
| `STR_MONTH_JAN` .. `STR_MONTH_ERR`         | months (`ERR` is the last member)     |

Their heads are emitted with explicit `= N` enum values as documentation of
intent; the values always equal the index in the merged order.

## Build integration

The generator is also the build hook. Point `extra_scripts` at it in the
app's `platformio.ini`; it then reads its settings from project options (or
`POCKETMAGE_I18N_CATALOGS` / `POCKETMAGE_I18N_OUT_DIR`, or the SDK base
catalog as a last resort):

```ini
extra_scripts = pre:lib/PocketMage_SDK/pocketmage_i18n/tools/gen_i18n.py

custom_i18n_catalogs =
    lib/PocketMage_SDK/pocketmage_i18n/languages
    src/i18n
custom_i18n_out_dir = .pio/build/${PIOENV}/i18n
```

As a hook it regenerates only when a `.po`/`.aliases` file is newer than the
generated tables, so incremental builds are cheap.

`custom_i18n_out_dir` must be on the include path ahead of any stale copy;
the engine includes `"pocketmage_i18n_gen.h"` and the generated files are
build artifacts, never committed.

## Adding a string or a language

- **String:** add the `msgctxt`/`msgid`/`msgstr` to the owning catalog's
  `en` file and to each language file, in the same position relative to that
  catalog's other strings. Put app strings in the app catalog.
- **Language:** append the code to the base `en` file's `# Languages:`
  directive and add that language's directory to each catalog that translates
  it. Never reorder existing languages: the index is the value stored in NVS.

## Testing

```sh
python3 -m unittest discover -s pocketmage_i18n/tests
```

The suite covers catalog merging, language fallback, alias merging, and every
validation failure above, using small in-test catalogs.
